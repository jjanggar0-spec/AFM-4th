# 냉장고 야식 레시피

냉장고 재료 DB에 **지금 실제로 있는 재료만** 써서 1인분 야식 한 편을 `week-1/quest/레시피북/` 에 남긴다.

`recipe-card` 스킬과의 차이는 딱 하나 — **재료를 상상하지 않는다.** 재료 목록이 곧 제약 조건이다.

## 워크플로

### 1. 재료 읽기

```bash
ls "week-4/quest/fridge-recipe/data/ingredients/"*.json
```

각 파일은 재료 1개다. 형식:

```json
{
  "id": 5,
  "name": "삼겹살",
  "category": "육류",
  "createdAt": "2026-09-15T08:49:16.244Z"
}
```

카테고리는 `채소 / 과일 / 육류 / 해산물 / 유제품·달걀 / 양념·소스 / 곡물·면 / 기타` 8종.

JSON이 없거나 오래됐으면 DB에서 다시 받는다 (아래 **재료 동기화**).

### 2. 재료 고르기

- **JSON에 있는 이름만 쓴다.** 없는 재료는 레시피에 올리지 않는다. 물·불은 예외다.
- 단, **물·소금 수준의 기본값**은 냉장고에 없어도 쓸 수 있다고 본다. 그 외(간장, 설탕, 버터 등)는 JSON에 있을 때만.
- 탄수화물 1 + 단백질 1 + 김치/채소 1 + 마무리 향(참기름·깨소금 등) 조합이 야식으로 가장 잘 붙는다.
- **레시피북에 이미 있는 요리와 겹치지 않게** 한다. 먼저 `ls "week-1/quest/레시피북/"` 로 확인.

### 3. 야식 제약

일반 레시피와 다른 부분이라 반드시 지킨다.

- **15분 이내.** 넘어가면 야식이 아니다.
- **냄비/팬 1개.** 설거지가 늘어나는 구성은 피한다.
- **양 조절 문구를 팁에 넣는다.** "밤에 부담될 때 — 고기를 절반으로 줄이고 국물을 늘린다" 처럼, 가볍게 먹는 방법을 항상 하나 적는다.
- 1인분 고정. 사용자가 다른 인분을 말하면 그걸 따르되 제목·본문에 반영한다.

### 4. 본문 작성

`recipe-card` 스킬의 마크다운 템플릿을 그대로 쓴다 (`.claude/skills/recipe-card/SKILL.md` 참고). 파일명은 `<요리명-케밥케이스>.md`, 한글 유지, 공백은 `-`.

야식 버전에서 추가로 지킬 것:

- 재료 줄 끝에 손질법을 붙인다. 밤에 머리 안 쓰고 따라갈 수 있어야 한다.
- 각 단계 소요 시간의 합이 제목의 분 수와 맞아야 한다.
- **팁에는 대체 재료를 냉장고 안에서 찾아 적는다.** "쌀국수가 없으면 소면으로" 처럼, 다른 JSON에 있는 재료로 제안한다.
- `곁들이면 좋은 것` 도 냉장고 재료 안에서 고른다.

### 5. 썸네일

`recipe-card` 의 `scripts/gen-thumbnail.ps1` 과 지브리풍 프롬프트 틀을 그대로 쓴다. 요리 묘사는 레시피의 실제 재료와 일치시킨다.

```powershell
& ".claude\skills\recipe-card\scripts\gen-thumbnail.ps1" `
    -OutPath "week-1\quest\레시피북\<슬러그>.png" `
    -Prompt  "<프롬프트>"
```

야식이므로 배경은 밤으로 간다 — `late at night`, `a small kitchen table`, `lamplight` 계열.

**401 Unauthorized 가 나면** `.claude/settings.local.json` 의 `GEMINI_API_KEY` 가 만료·폐기된 것이다. 키를 채팅에 요구하지 말고, 이미지 없이 본문만 저장한 뒤 사용자에게 키 갱신이 필요하다고 알린다. 이미지 링크 줄은 넣지 않는다 — 깨진 링크가 남는 것보다 낫다.

생성에 성공했으면 Read 도구로 PNG를 직접 열어 재료가 맞는지 확인한 뒤 제목 바로 아래에 삽입한다.

## 재료 동기화

JSON은 Supabase `ingredients` 테이블의 스냅샷이다. 앱에서 재료를 추가·삭제했으면 다시 받아야 한다.

```bash
node ".claude/skills/fridge-midnight-snack/scripts/sync-ingredients.js"
```

`week-4/quest/fridge-recipe/.env` 의 `DATABASE_URL` 을 읽어 `data/ingredients/` 를 통째로 다시 쓴다. DB에서 지워진 재료의 파일도 같이 지운다.

서버가 떠 있으면 API로 확인해도 된다: `curl -s localhost:3300/api/ingredients` (포트는 `.env` 확인).

## 주의

- **경로 주의** — 레시피북은 `week-1/quest/레시피북/` 이다. `recipe-card/SKILL.md` 에는 `week-1/quesks/...` 로 적혀 있는데 오타다.
- `.env` 의 `DATABASE_URL` 은 절대 커밋되는 파일에 옮겨 적지 않는다.
- 커밋은 사용자가 요청할 때만. 메시지는 한국어 `<요리명>: <변경 요약>` 형식이고 `.md` 와 `.png` 를 같은 커밋에 넣는다.
