# 지역 업체 리서치 — 분석 방법과 보고서 틀

"Area 안 업체 요약 + 특정 업체 부정 리뷰 분석"형 리서치에 쓴다.
예시 결과: `week-5/quest/Reserch/구리눈NOON안과 반경5km(2026-10-08).md` / `.html`. 처음 만들 때 열어서 구성과 톤을 참고한다.

---

## 1. 데이터 → 통계 (node)

수집한 JSON(`naver-place-scripts.md` §3·§4·§5)을 node로 가공한다. 곳마다 아래 값을 낸다.

| 지표 | 계산 |
|---|---|
| n | 중복 제거 후 표본 수 (`date + text.slice(0,80)` 키) |
| 기간 | 표본의 최소~최대 방문일 |
| 빠른 입장 % | 대기 태그 중 (바로 입장 + 10분 이내) / 태그 수 |
| 1시간+ % | (1시간 이상 + 2시간 이상) / 태그 수. **태그가 10건 미만이면 "–"** 로 둔다 |
| 답글 % | reply true / n |
| 테마 언급 수 | 정규식으로 셈: 친절 `/친절/` · 설명 `/설명/` · 꼼꼼 `/꼼꼼\|세심\|자세/` · 과잉없음 `/과잉.{0,4}(없\|안)/` · 수술 `/백내장\|라식\|라섹\|스마일\|렌즈삽입\|수술/` · 아이 `/아이\|아기\|아들\|드림렌즈\|소아\|초등/` · 시설 `/깨끗\|깔끔\|시설/` · 주차불편 `/주차.{0,6}(불편\|힘들\|어렵)/` |
| 부정 후보 | 아래 정규식에 걸린 리뷰 (태그 부분은 빼고 본문만 검사) |

부정 후보 정규식 (1차 필터용):

```js
/불친절|별로|실망|최악|불쾌|짜증|화가|화나|기분 ?나|비싸|과잉|강요|오래 기다|기다리|대기.{0,6}(길|오래|많)|아쉽|아쉬|불편|다시는|비추|성의|대충|무시|퉁명|상술|영업|장사|권유|불만|어이|황당|무례|엉망|돈만|ㅡㅡ|;;|\?\?|안 ?가요|안갈|비용이|비쌈|딱딱|쌀쌀/
```

이 정규식은 "과잉진료 **없어요**", "기다렸지만 **만족**" 같은 긍정 리뷰도 잡는다. 반드시 하나씩 직접 읽고 분류한다.

- **뚜렷한 부정**: 리뷰의 주된 내용이 불만이다.
- **불만 섞인 긍정**: 전체로는 만족했지만 구체적인 불만이 하나 있다.
- **제외**: 불만 단어가 부정 맥락이 아니다.

부정 비율 = (뚜렷한 부정 + 불만 섞인 긍정) / n. Area 비교에서는 **중앙값**을 함께 적는다.

## 2. 대상 업체 부정 리뷰 분석 순서

1. **전수 수집**: 네이버 전체, 카카오 전체, 블로그 3~5편.
2. **분류**: 뚜렷한 부정 / 불만 섞인 긍정. 출처별 표를 만든다(전체·부정·비율).
3. **유형 집계** (중복 허용). 병원 기준 유형은 다음과 같다.
   - ⏱ 대기·예약
   - 🙍 직원(데스크·간호·검안) 응대
   - 🩺 의사 설명·태도
   - 💸 과잉검사·비용
   - 🪑 시설·주차·좌석
   - 🧤 위생·처치 통증
   - 💊 처방
   - 다른 업종이면 맞게 바꾼다.
4. **원문 요약 표**: 날짜, 출처, 대기 태그, 원문 발췌(따옴표), 병원 답글 여부.
5. **분석**: 아래 여섯 가지를 각각 근거와 함께 쓴다.
   - ① **핵심 원인**: 가장 많은 유형이 왜 생기는지 설명한다. 병원 답글에 운영 방식 설명이 있으면 인용한다(예: "예약은 검사 시작 기준").
   - ② **양면성**: 같은 특징(검사 많음, 설명 김)을 긍정으로 본 리뷰와 부정으로 본 리뷰를 나란히 놓는다. 불만이 몰리는 환자 유형(예: 가벼운 증상)도 적는다.
   - ③ **Area 비교 표**: 부정 비율, 대기 1시간+, 빠른 입장, 주된 불만 유형, 답글 비율. 비교 대상은 비슷한 규모의 업체로 고른다.
   - ④ **시기별 흐름**: 부정이 몰린 달, 확장·이전 같은 이벤트 전후 변화.
   - ⑤ **병원 대응**: 답글 비율, 반복되는 문구, 답글을 몰아서 단 날짜, 구체적인 개선 내용이 있는지.
   - ⑥ **리뷰 몰림 패턴**: 특정 달에 짧은 긍정 리뷰가 몰렸는지, 대기 태그가 없는 리뷰 비율, 카카오 5점이 몰린 주. "부탁받아 썼는지는 확인 못 함"이라고 반드시 적는다.
6. **반대 의견**: 불만과 반대되는 긍정 리뷰를 2~3개 인용한다.

## 3. Area 요약 순서

1. **지역별 분포**: 생활권 단위(역 앞·신도시·옆 구)로 묶고 특징을 한 줄씩 쓴다.
2. **비교표**: 거리, 전문의 수, 리뷰 총계, 표본(기간), 빠른 입장 %, 1시간+ %, 부정(건수·%), 진료시간 특이점(일요일·야간·조기마감).
3. **곳별 한 줄 요약**: 👍 강점(테마 언급 수와 대표 표현) / 👎 약점(부정 리뷰 요지). 부정이 없으면 "표본에서 부정 없음"이라 쓰고, 표본이 짧은 기간에 몰려 있으면 그 사실도 쓴다.
4. **패턴 4~6개**를 수치와 함께 쓴다. 예:
   - 규모에 따라 불만 유형이 다르다.
   - 자주 나오는 칭찬 키워드가 있다.
   - 특정 지역에 특정 수요가 몰린다.
   - 일요일·야간 대안이 있다.
   - 리뷰가 몰린 곳이 있다.
   - 답글을 다는 정도가 다르다.

## 4. `.md` 틀

````markdown
# {기준 업체} 반경 {N}km {업종} 리서치 · {대상 업체} 부정 리뷰 분석

- 조사일 / 조사 도구 / 범위(Area, 분석 대상) / 수집 규모 / 검색어
> ⚠️ 한계: 조사 시점 기준, 직선거리, 표본 기간이 곳마다 다름, 키워드 필터 한계, 실명 제외

## 1. 한눈에 보기          ← 질문 | 답 표 (Area 수, 큰 곳, 일요일·야간, 주변 불만, 대상 부정 비율, 약점, 강점)
## 2. Area {업종} 리서치 요약 ({N}곳)
### 2-1. 지역별 분포
### 2-2. 비교표 (거리순)
### 2-3. 곳별 한 줄 요약
### 2-4. Area 전체에서 보이는 패턴
## 3. {대상 업체} 부정 리뷰 정리·분석
### 3-1. 기본 정보   ### 3-2. 부정 리뷰 규모   ### 3-3. 유형별 집계
### 3-4. 뚜렷한 부정 리뷰   ### 3-5. 불만 섞인 긍정 리뷰
### 3-6. 분석 (①~⑥)   ### 3-7. 반대 의견
## 4. 결론 — 상황 | 참고 | 근거 표 (단정하지 않음)
## 5. 참고한 글   ## 6. 출처
````

## 5. `.html` 구성 (데이터는 `<script>` 안 배열로)

- 헤더, 목차 칩(`#summary #area #noon #conclusion #sources`), 한계 박스
- 1장: 요약 카드 4개 + 질문/답 목록
- 2장
  - 지역 카드
  - **비교표**: 지역 필터 칩, 진료 필터 칩(일요일·야간), 열 정렬. 비율은 작은 막대로(빠른 입장=초록, 1시간+=주황, 부정=빨강). 안과 이름은 네이버 리뷰 페이지 링크로. 기준 업체 행은 강조.
  - 곳별 `<details>`: 강점(초록)/약점(빨강)/근거(회색). 위 필터가 같이 적용된다. "부정 많음(15%+)", "대기 김(10%+)" 태그를 붙인다.
  - 패턴 카드
- 3장
  - 요약 카드
  - 유형별 막대
  - 분석 카드: ②는 긍정/부정 나란히, ③은 비교 표, ④는 타임라인
  - 부정 리뷰 카드: 유형·구분·출처 필터. 왼쪽 테두리 빨강=뚜렷한 부정, 주황=불만 섞인 긍정. 답글 태그를 붙인다.
- 4장: 결론 카드. 출처.
- 검증 때 evaluate로 확인할 것
  - 필터별 건수 (예: 일요일 칩 → 일요일 진료 곳 수)
  - 정렬 1위 (부정 정렬 → 부정 비율 최고 업체)
  - 유형별 건수와 데이터 배열의 합이 맞는지
